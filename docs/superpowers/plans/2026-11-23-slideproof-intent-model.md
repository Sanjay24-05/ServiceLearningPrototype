# Slide Proof AI Intent Model Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a small, local, explainable machine-learning model that judges whether each "sticks out" (C1) or "overlap" (C2) finding is a deliberate design choice. Confident cases move into a "Probably intentional" section with a spoken reason. The model is trained on synthetic decks and documented in a model card.

**Architecture:**
- **New package `slideproof/intent/`:**
  - `features.py`: raw candidates and their feature vectors;
  - `__init__.py`: `judge()`, loading the shipped model.
- **Two new tools:**
  - `make_training_decks.py`: synthetic decks with labelled deliberate patterns and mistakes;
  - `train_intent_model.py`: trains, evaluates and writes the model, metrics and model card.
- **Wiring:**
  - `analyse()` calls `judge()` between the checks and the prioritiser;
  - the prioritiser gains a third tier;
  - the report and the "How it works" page show the new section and the measured accuracy.

**Tech Stack:** existing, plus `scikit-learn==1.5.2` (pinned; verified downloadable on this network) and `joblib` (comes with it).

**Spec:** `docs/superpowers/specs/2026-11-22-intent-model-and-polish-design.md` §5 (Part A) and §6 item 4. Main spec `docs/superpowers/specs/2026-11-20-slide-layout-checker-design.md` §5.3 (checks never produce prose) and §8.

**Base branch:** `master` (7bc7038, Presentable merged). Work on a new branch, `ai-model`.

## Global Constraints

- Everything runs locally. No network at training or run time. Training uses only generated data.
- **The model never hides a finding.** "Probably intentional" findings stay listed and their fixes stay available, unticked. The summary always counts them.
- **Safety first:**
  - at least 95% of held-out synthetic mistakes must stay in the main lists;
  - every planted mistake in the demo deck and in `tools/make_test_decks.py` decks must stay in the main lists;
  - when the two targets conflict, mistake recall wins.
- Threshold: `intent_p ≥ 0.80`, unless the training evaluation picks a stricter value to keep mistake recall ≥ 95%. The chosen value is stored in `features.json`.
- If scikit-learn is missing, its version differs from the one in `features.json`, or the model can't load: findings are unchanged and the report shows `The "probably intentional" judgement is unavailable in this setup.` It never fails silently.
- The model judges **only C1 and C2 findings that survive today's rules**. The §7.2 exemptions stay exactly as they are.
- The model card states in its first paragraph: "All training data is synthetic."
- Exact copy (design §5.5):
  - **Summary:** `… {m} minor, {k} probably intentional.` (the clause is omitted when k = 0)
  - **Section:** `<h2>Probably intentional ({k})</h2>` followed by `<p>Slide Proof's model thinks these look like deliberate design. Check them if you are unsure.</p>`
  - **Per finding:** `Probably intentional ({pct}% sure): {reason 1}{ and reason 2}.`
  - **Reason phrases:**
    - `repeats`: "the same object appears in the same place on {n} other slides"
    - `edges`: "it runs along the edge of the slide like a design element"
    - `span`: "it spans the full width or height of the slide"
    - `no_text`: "it contains no text"
    - `behind`: "it sits behind the other objects"
    - `layout`: "it comes from the slide's layout"
  - **Coverage sentence addition:** `A small on-device model sorts findings that look like deliberate design into "Probably intentional".`

## Review Focus

1. **A real deck whose findings are all plausible mistakes** (the demo deck, the constructs deck): nothing may move. → Task 4 test.
2. **Model files missing, or a different scikit-learn version installed:** the report still works and says the judgement is unavailable. → Task 4 test.
3. **A grouped finding (more than 5 on one slide) whose members fall in different tiers:** grouping happens within a tier and never mixes tiers. → Task 4 test.
4. **A "Probably intentional" finding with a fix:** its checkbox is unticked, the fix still works when ticked, and verify treats it as a normal finding. → Task 5 test.
5. **Training is reproducible:** the same seed gives the same model metrics. → Task 3 test.

### Task 1: Features and raw candidates

**Files:** Create `slideproof/intent/__init__.py` (an empty placeholder for now) and `slideproof/intent/features.py`. Test: `tests/test_intent_features.py`.

**Interfaces:**
- Consumes:
  - `DeckModel`, `Element` (with `frame`, `bbox`, `z`, `kind`, `text`, `filled`, `placeholder_type`, `group_id`, `rotation`, `slide_index`);
  - `SlideModel.layout_key`;
  - `content_box(el)` from `slideproof.checks.content`;
  - `Finding`.
- Produces:
  - `FEATURES: list[str]`, in this order: `is_c1, is_c2, magnitude, edges_touched, span_w, span_h, area_share, has_text, kind_picture, kind_shape, kind_text, kind_other, is_placeholder, in_group, z_rank, repeats, same_layout_repeats, elements_on_slide, rotated, lower_is_text, upper_inside_lower`
  - `@dataclass Candidate: check_id: str; slide_index: int; element_ids: tuple[str, ...]; magnitude: float`
  - `raw_candidates(deck) -> list[Candidate]`:
    - **C1:** every non-empty element whose bbox lies more than 2% outside the slide (no bleed exemption).
    - **C2:** every (upper, lower) pair where the upper element is a picture or filled shape covering ≥ 5% of the lower element's `content_box` (no §7.2 exemptions). `element_ids` is (upper, lower), as for C2 findings.
  - `features_for(check_id, element_ids, magnitude, deck) -> list[float]`, in `FEATURES` order. Takes plain values so it serves both Candidates and Findings.
- **Feature definitions:**
  - `edges_touched`: count of slide edges the first element's bbox reaches within 0.05 in, or crosses.
  - `span_w`, `span_h`: bbox width ÷ slide width and height ÷ slide height, capped at 2.
  - `z_rank`: the element's index among its slide's elements by z, ÷ (n − 1), or 0 when n = 1.
  - `repeats`: number of *other* slides with an element of the same kind whose frame x, y, w and h are each within 0.1 in.
  - `same_layout_repeats`: the same, counted only on slides with the same `layout_key`.
  - `kind_text`: covers title, body and textbox.
  - `lower_is_text`: C2 only; 0 for C1.
  - `upper_inside_lower`: C2, upper bbox contained in lower bbox; 0 for C1.

### Task 2: Synthetic training-deck generator

**Files:** Create `tools/make_training_decks.py`. Test: `tests/test_training_decks.py`.

**Interfaces:**
- Produces `build_training_decks(out_dir: Path, n_decks: int, seed: int) -> list[Path]`. It is also a CLI: `python tools/make_training_decks.py <out_dir> [n_decks=120] [seed=7]`.
- **Each deck:**
  - 6–10 slides, 16:9 or 4:3 at random;
  - built from Title Only, Title and Content and Blank layouts;
  - realistic content: titles, bullet text, pictures made with Pillow, and some tables.
- **On each deck:**
  - 2–4 **deliberate** patterns from design §5.3, each named `deliberate-<pattern>-<n>`:
    - full-bleed photo;
    - edge banner;
    - edge half-circle;
    - corner badge;
    - repeated corner logo on every slide;
    - footer bar on every slide;
    - stacked-shape icon;
    - caption band inside a photo;
    - frame behind a picture;
    - text on a coloured panel.
  - 2–4 **mistake** patterns, each named `mistake-<pattern>-<n>`:
    - text box nudged past one edge by 10–60%;
    - picture dragged over a text box covering 10–80%;
    - a box partly off the slide;
    - a duplicate offset onto its original;
    - a resized picture spilling over the title.
- **Randomness:** all positions, sizes and colours are drawn from the same ranges for both classes wherever the pattern allows.
- **Labels:** the labelling rule lives in Task 3: a candidate is labelled by the name prefix of any element involved.

### Task 3: Training, evaluation, model card

**Files:**
- Create: `tools/train_intent_model.py`
- Generated and committed: `slideproof/intent/{model.joblib,features.json,metrics.json}`, `docs/ml/intent-model-card.md`
- Modify: `requirements.txt` (add `scikit-learn==1.5.2`)
- Test: `tests/test_intent_model.py`

**Interfaces:**
- Produces `train(out_model_dir: Path, card_path: Path, n_decks: int = 120, seed: int = 7) -> dict`, which returns the metrics. CLI: `python tools/train_intent_model.py [--quick]`, where `--quick` means 12 decks and is used by tests.
- **Dataset:**
  - build the decks into a temp folder;
  - run `raw_candidates`;
  - label each candidate: if any element name starts with `deliberate-` → 1 (deliberate); else if any starts with `mistake-` → 0; else drop it;
  - features from `features_for`;
  - group = deck index.
- **Models:**
  - (a) `make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000, class_weight="balanced"))`
  - (b) `HistGradientBoostingClassifier(random_state=seed)`
- **Evaluation:** `GroupKFold(n_splits=5)`, out-of-fold probabilities.
  - **Threshold:** the smallest t ≥ 0.80 on a 0.01 grid where mistake recall (the share of label-0 rows with p < t) is ≥ 0.95. If none exists, t = 0.99 and the card says the target was missed.
  - **Report for each family:** at t, mistake recall, deliberate recall, precision, F1 and the confusion matrix.
  - **Ship:** logistic regression, unless gradient boosting's F1 is more than 0.05 higher, in which case ship gradient boosting.
  - Refit the shipped family on all data and save it with joblib.
- **Held-out real-deck check:** run the checks and the shipped model on:
  - the demo deck (`slideproof.demo_deck`);
  - `tools/make_test_decks.py` decks;
  - the Yellow Idea template, if LibreOffice and the template exist.

  Record how many planted mistakes would move (must be 0) and how many Yellow Idea findings would move. Both go in `metrics.json`.
- **`features.json`:** `{"version": 1, "features": FEATURES, "sklearn": sklearn.__version__, "threshold": t, "family": "logreg" | "hgb"}`
- **Model card:** a template filled from the metrics, with sections:
  - purpose;
  - **All training data is synthetic** (first paragraph);
  - patterns and ranges;
  - class counts;
  - metrics table for both families;
  - threshold;
  - held-out real-deck results;
  - known limits;
  - how to retrain.

### Task 4: `judge()` and the third tier

**Files:** Modify `slideproof/intent/__init__.py`, `slideproof/prioritise.py`, `slideproof/analysis.py`. Test: `tests/test_intent_pipeline.py`.

**Interfaces:**
- **`judge(findings, deck) -> tuple[list[Finding], str | None]`:**
  - Returns new findings, and a note when the model is unavailable.
  - For each C1/C2 finding, adds to a copy of its measurements:
    - `"intent_p"`: float;
    - `"intent_reasons"`: up to 2 codes from `repeats`, `edges`, `span`, `no_text`, `behind`, `layout`, picked by the largest positive contributions to "deliberate".
  - **Contributions:** for logistic regression, coefficient × standardised value per feature, mapped to codes:
    - `repeats` / `same_layout_repeats` → `repeats`
    - `edges_touched` → `edges`
    - `span_w` / `span_h` → `span`
    - `has_text` (negative value) → `no_text`
    - `z_rank` (low) → `behind`
    - `is_placeholder` → `layout`

    For gradient boosting, use the same codes from simple rules on the raw feature values.
  - Model loading is cached per process.
- **`Report` gains `intentional: list[Finding]`, defaulting to empty.**
  - `prioritise()`: a finding with `intent_p ≥ threshold` goes to `intentional`; the rest keep visible/minor as today.
  - Grouping runs **separately per tier**.
  - `slides_with_visible` counts only the visible tier.
- **`Analysis` gains `intent_note: str | None`.** `analyse()` calls `judge()` after `run_checks()` and passes the threshold to `prioritise()`.
